# Competitive SEO Audit

A repeatable methodology for auditing and comparing the SEO structure of multiple websites. Used for competitive analysis, site planning, or benchmarking before building a new site in a competitive space.

## Methodology

### Per site, per page type, collect:

**Always collect for BOTH homepage AND at least one detail/content page.**

| Element | How to Extract |
|---------|---------------|
| **Page title** | `<title>` in `<head>` |
| **Meta description** | `name="description"` meta tag |
| **Canonical URL** | `rel="canonical"` link tag |
| **OG tags** | `property="og:title"`, `og:description`, `og:image`, `og:type` |
| **Twitter cards** | `name="twitter:card"`, `twitter:title`, `twitter:description` |
| **H1 text** | `<h1>` tag content |
| **H2-H6 structure** | `<h2>`–`<h6>` tags — list their text content |
| **JSON-LD schema** | All `<script type="application/ld+json">` blocks, parse + inspect |
| **Microdata** | `itemscope`/`itemtype`/`itemprop` attributes |
| **Breadcrumbs** | Visible breadcrumb nav AND `BreadcrumbList` schema |
| **Canonical presence** | Present or missing |
| **URL structure** | Pattern: hierarchical vs flat, slug format |

### Always check infrastructure:

| Element | How to Check |
|---------|-------------|
| **robots.txt** | `curl -sSL "https://site.com/robots.txt"` — note allow/disallow rules, AI crawler blocks, sitemap references |
| **Sitemap** | `curl -sSL "https://site.com/sitemap.xml"` — count entries, check sub-sitemaps, note coverage |
| **Page generator** | `name="generator"` meta tag (WordPress, Webflow, etc.) |
| **Response headers** | `curl -sSL -D - "URL" >/dev/null` — caching, content-type |

### Internal linking analysis:

For each page type, grep for same-site `href` URLs:
```bash
grep -oP '(?<=href=")https?://site\.com/[^"]*' page.html | sort -u | head -30
```

### Cross-competitor comparison:

After collecting data for all sites, produce a gap table:

| SEO Factor | Site A | Site B | Your Opportunity |
|-----------|--------|--------|-----------------|
| Page Titles | What pattern | What pattern | ✅ Better pattern |
| Meta Descriptions | Generic or specific | Same | ✅ Unique per page |
| JSON-LD Schema | Present/absent | Same | ✅ Add missing types |
| Breadcrumbs | Visible + schema | None | ✅ Add both |
| ... | ... | ... | ... |

## Pitfalls

1. **Browser tool readiness** — If Chromium isn't installed, `browser_navigate` times out. For SEO analysis, `curl` + `grep` on saved HTML is faster and more reliable. Use the browser only when you need to interact with JS-dependent content (infinite scroll, dynamic filters).
2. **JSON-LD grep artifacts** — Terminal display can mangle `@context` values. Always parse JSON-LD with `json.loads()` not grep.
3. **Large HTML files** — Homepages can be 300K+ bytes. Save to `/tmp/` with `curl -o` before extracting; don't pipe directly.
4. **Sitemap truncation** — Large sitemaps (>50K entries) may be split across sub-sitemaps. Always check the sitemap index first.
5. **React/SPA content** — Pages rendered client-side won't have heading tags or structured HTML in the `curl` output. Use `browser_navigate` + `browser_console(expression)` to extract the DOM tree.
6. **Webflow sites** — Generated by Webflow, identified by `<meta name="generator" content="Webflow"/>`. OG image URLs point to `cdn.prod.website-files.com`. This doesn't affect SEO quality but helps you recognize the platform.
7. **Not all models get sitemap coverage** — HuggingFace has 2.9M models but only 5,718 in the sitemap. Cross-reference sitemap coverage against total inventory.

## Verification

After producing the report, spot-check at least one finding on each site by re-fetching the relevant element. If a meta tag or schema block differs from what's in your report, you may have hit an A/B test or dynamic content variant.
